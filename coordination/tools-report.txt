Shared integration:
- FeatureActivity.open(Context, characterId, instanceId). Empty/unknown character opens all six tools. No UiKit methods beyond contract.
- Call ReminderScheduler.reschedule(Context) at main startup. It reschedules only user-enabled reminders; it never starts overlay or microphone. Overlay screen-on/resume/reload calls public ReminderScheduler.deliverPendingFeedback(Context) after slots are ready, to show only the newest meaningful reminder missed during screen-off. The method checks canReceiveFeedback("doro") BEFORE writing reminder_latest_feedback and never starts a service. ReminderReceiver uses this same method rather than broadcasting directly, so main startup, alarm receiver, and overlay resume all share the readiness gate. Separately opted-in background notifications remain available without a Doro window.
- PetStore.add for sweat_emoji should initialize mood from mood_default (default sweating) and moodText from mood_text_default (default empty). Existing instances are updated individually through PetStore.update.
- Overlay already reads comfort_reset_token and ThursdayRules.state / claimCelebration. State strings emitted and checked against catalog.json: doro water/fruit/satisfied; panda writing/recording/saved/tearing; mood sweating/happy/sad/angry/speechless/sleepy/shy/shocked; kinship result; Thursday crazy/calm. FeatureActivity accepts stored wronged as sad when opening the picker. No new code emits wronged.
- ThursdayRules.refresh only requests settings reload. The visible overlay owns claimCelebration, so opening the app while overlay stopped does not consume first-appearance celebration. Date history prevents repeats when clock rolls back to an already celebrated date.
- Main should apply the shared three-color theme to native TimePicker/AlertDialog chrome as well as custom controls. All tool-created controls use UiKit colors/tints.
- Notes live in gengpet_notes.db, audio in files/recordings. Export provider only serves saved row IDs, read-only, with temporary URI grants.

Known scope/limits:
- Recording deliberately stops and preserves usable audio on Activity pause (home/lock/rotation/interruption). It does not continue in background. Draft metadata recovery validates playable duration; unfinished/corrupt media can be explicitly deleted. Completed files orphaned between rename and SQLite commit are also offered for recovery.
- Full-body text draft survives Activity pause in preferences; it is not a committed note until Save. No automatic speech transcription.
- Kinship rules cover common Mandarin relationships and explicitly decline unsupported complex chains, adoptive/step-family assumptions and alternative marital models; cousin age is never inferred from parent's sibling order.
- Notification and alarm delivery can be delayed by OS/OEM power management. The two business schedules have separate pending intents, revisions and notifications; old task/action tokens are rejected.
- Thursday auto-animation and comfort rendering remain overlay implementation; tool code supplies persistent controls and shared rule entry points.

Platform sources checked during implementation: https://developer.android.com/reference/android/media/MediaRecorder and https://developer.android.com/develop/background-work/services/alarms .

FINAL ERROR/STATE REVIEW (after GengMainActivity landed):
- Fixed DATE_CHANGED handling: ordinary midnight now preserves an already scheduled cross-midnight snooze. Only actual TIME_SET/TIMEZONE_CHANGED discards obsolete wall-clock triggers and clears old pending/dedup state.
- Fixed stale notification actions: respond rejects disabled, missing, future-dated and >2-hour-old pending reminders; notifications have a matching remaining lifetime. Startup preserves one still-relevant overdue reminder before replacing a delayed alarm. Quiet periods remain start-inclusive/end-exclusive across midnight; snooze rounds upward and is never shorter than the requested duration.
- Configuration revisions use fresh random tokens on each save/clock rebuild, so clearing preferences and reenabling cannot recreate an old generation number. Confirmed current GengMainActivity.deleteData clears prefs and calls reschedule: both alarm identities are cancelled, both notifications are cancelled, and disabled config clears pending/snooze values. Queued old receivers fail enabled/due/revision checks. No main-file change needed.
- Pending feedback uses the newly available GengOverlayService.canReceiveFeedback("doro") readiness check before consuming it. Thus absent/hidden/unready Doro instances do not lose pending feedback; the overlay's own pendingFeedback callback invokes delivery after readiness changes. Only the newest meaningful pending reminder is emitted.
- Recording stop errors no longer delete a nonempty file merely because MediaRecorder.stop threw. They retain a recoverable draft, whose actual playable duration is checked before database save. Explicit cancel still deletes; deletion failure is reported rather than falsely claiming success. Recorder/focus cleanup is guarded, including constructor/start/release failures.
- NotesPanel pause is idempotent, preventing duplicate autosaves and an onDestroy callback from rewriting a draft after an already-paused screen. Returning to recording UI refreshes its stopped state. Recording metadata is committed only after finalized local media validates.
- Share review: ACTION_SEND includes both EXTRA_STREAM and ClipData plus read-only grant; provider exported=false/grantUriPermissions=true; provider accepts only saved numeric row IDs and read mode, no raw file path. Deleting a recording now revokes its granted read URI. Files already opened by another application cannot be retroactively unread; this is normal shared-file semantics.
